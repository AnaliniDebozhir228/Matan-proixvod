## Решения

### Задание 1. Подсчёт циклов

| Фрагмент | Количество выполнений | Порядок роста |
|---|---:|---|
| Один цикл `for i in range(n)` | n | O(n) |
| Два вложенных цикла по n | n² | O(n²) |
| Цикл с `i *= 2` | около log₂(n) | O(log n) |

В третьем фрагменте точное число повторений при n > 1 равно ⌈log₂(n)⌉.

### Задание 2. Бинарный поиск

Реализована функция `binary_search`, которая возвращает индекс найденного элемента и число проверок середины.

Для списка `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`:
- x = 23 → индекс 5, за 3 шага;
- x = 7 → не найдено (индекс -1), за 3 шага.

### Задание 3. Максимальное число шагов бинарного поиска

- Для 1000 элементов: ⌈log₂(1000)⌉ = 10 шагов.
- Для 1 000 000 элементов: ⌈log₂(1 000 000)⌉ = 20 шагов.

### Задание 4. Сравнение сортировок

Реализованы пузырьковая сортировка `bubble_sort` и сортировка слиянием `merge_sort`. Время измеряется через `time.perf_counter()`; для каждого размера берётся медиана трёх запусков.

Пример одного запуска:

| Размер списка | Пузырёк, сек. | Слияние, сек. |
|---:|---:|---:|
| 1000 | 0.0393 | 0.0012 |
| 2000 | 0.1656 | 0.0026 |
| 4000 | 0.6209 | 0.0055 |

При удвоении n пузырьковая сортировка стала медленнее примерно в 4 раза, сортировка слиянием — примерно в 2 раза. Это соответствует ожидаемому росту O(n²) и O(n log n). Время зависит от компьютера, поэтому при повторном запуске значения могут отличаться.

### Задание 5. Жадный выбор мероприятий

Функция `max_events` сортирует мероприятия по времени окончания и выбирает следующее, если оно начинается не раньше окончания предыдущего.

Для примера из конспекта выбран набор:
`(1, 4), (5, 7), (8, 11), (12, 16)` — всего 4 мероприятия.

Контрпример для правила «брать самое короткое»: `(1, 5), (4, 7), (6, 10)`. Самое короткое мероприятие — `(4, 7)`; если выбрать его, остальные два уже не подходят. Получится 1 мероприятие. Оптимально выбрать `(1, 5)` и `(6, 10)` — 2 мероприятия.

### Задание 6. Лесенка

Пусть dp[n] — количество способов подняться на n ступенек. Последний шаг может быть на 1 или на 2 ступеньки, поэтому:

`dp[n] = dp[n - 1] + dp[n - 2]`

Начальные значения: dp[0] = 1, dp[1] = 1. Получается последовательность Фибоначчи со сдвигом на один элемент.

- n = 1 → 1 способ;
- n = 2 → 2 способа;
- n = 10 → 89 способов;
- n = 30 → 1 346 269 способов.

### Задание 7. Размен монет

Для монет `{1, 3, 4}` сравнены жадный алгоритм и динамическое программирование. Жадный алгоритм даёт неоптимальный ответ для сумм:

**6, 10, 14, 18.**

Например, для суммы 6 жадный алгоритм выбирает 4 + 1 + 1 (3 монеты), а оптимальный ответ — 3 + 3 (2 монеты).

### Задание 8. Алгоритм Евклида

Вычисление НОД(252, 198):

```text
252 = 1 * 198 + 54
198 = 3 * 54 + 36
54 = 1 * 36 + 18
36 = 2 * 18 + 0
```

**НОД = 18. Понадобилось 4 деления.**

### Задание 11. Алгоритм Дейкстры

Для графа из конспекта расстояния от A:

- A = 0;
- B = 3;
- C = 1;
- D = 4.

Кратчайший путь до D: A → C → B → D, длина 4.

После добавления ребра A–D длиной 3 кратчайшее расстояние до D становится **3** (напрямую A → D).

### Задание 12. Метод Монте-Карло

Реализована функция `monte_carlo_pi`. Для воспроизводимости используется фиксированное начальное значение генератора случайных чисел (seed = 42).

Пример результатов:

| N | Приближение π |
|---:|---:|
| 100 | 3.120000 |
| 10 000 | 3.126000 |
| 1 000 000 | 3.140592 |

При увеличении количества случайных точек оценка обычно становится точнее, но метод Монте-Карло не гарантирует, что каждое следующее значение будет ближе к π.
